光邮离线工具 1.4 · Cimbar + 普通二维码文本

新增“普通二维码（文本）”页：静态生成、摄像头/图片识别、手动二维码参数、UTF-8/ECI 编码、PNG/SVG 和 TXT 保存。详见 QR-TEXT-README.txt。

以下为原 Cimbar 低密度核心 1.3 的使用说明：

光邮 Cimbar · Windows 低密度核心版 1.3

解压后直接打开 Cimbar-Offline.html。无需安装 Node.js、Python 或服务器，无需联网。
两端都使用新版 HTML。浏览器仍需允许 WebAssembly、WebGL 和摄像头访问。
本次仅优化 Windows 浏览器端，附带的既有安卓 APK 未改动。

新增密度档位（真正的网格配置）
- Low：64×48 符号，原生码图 592×448，含边框显示 608×464。
- UltraLow：48×36 符号，原生码图 448×340，含边框显示 464×356。
- Micro 保留原有 80×69 网格，其他原模式也保留。
Low / UltraLow 是本工具的扩展格式，旧版本及官方安卓应用不能接收这两档。
它们减少了每帧数据量，不保证传输一定更快。请发送端全屏，保持相似显示面积，
这样低密度的符号才会更大；整数像素倍率不足时可对比“尽量铺满屏幕”。
停止接收后再切换密度，切换会清空接收进度。先用小文件比较完整接收时间。

推荐操作
1. 收发两端选择相同模式。先用 Low 64×48，仍不稳定时选 UltraLow 48×36；收发两端必须更新至 1.3 并选择相同档位。
2. 发送端全屏，保留“整数像素优先”，速度先设为 1–3 帧/秒。
   “屏幕像素倍率”小于 1 表示画面仍被缩小，应全屏或使用低密度模式。
3. 接收端默认请求 1920×1080；以“实际采集”显示的数值为准。
   保留“失败后增强重试”，保持码图完整、尽量大且清晰，避开反光。
4. 提示“未能定位四角”时，固定摄像头，点击“冻结并选四角”，依次选择：
   左上 → 右上 → 右下 → 左下，然后点击“应用四角”。
   请选择完整码图的外边界，包含定位标记；不要点定位标记中心或整个显示器边框。
   选错可撤销一角；位置变化后重新选择。应用后恢复实时接收。
5. 提示“已定位码图，但数据读不出”时，核对收发模式，再调整对焦、曝光和发送速度。
   在“对焦与曝光”中，摄像头支持时可手动调焦或降低曝光补偿。
   滑块禁用表示摄像头或浏览器未提供相应接口。
6. 参考接收端显示的解码耗时和建议发送速度。建议速度是估算值，不是测得的传输速率。
7. 接收完成后保存文件，核对两端 SHA-256。未填写发送端哈希时不会显示“核对通过”。

改进
- 整数屏幕像素显示，减少可避免的分数缩放；空间不足时给出提示。
- 原图优先；本帧未读齐时，尝试统一 RGB 清晰增强及尺度重试，每帧最多三次。
- 每次尝试读到的数据块都送入官方喷泉解码器，不混合不同时间的图像。
- 手动四角透视校正，并先裁掉外围背景，保留更多采样细节。
- 显示定位/内容解码失败原因、尝试路径、耗时和有效帧比例。
- 硬件支持时可控制手动对焦和曝光补偿，可选择采集分辨率。

使用边界
严重离焦、运动模糊和过曝已经丢失的细节不能凭软件恢复。B 模式比 Micro 更密，
本版不保证你的摄像头一定能稳定使用 B/Bm。有效帧比例包含重复画面，不等于文件进度。
停止、重开、切换接收模式或刷新会丢失进度；裁剪、选四角和调焦可在会话中调整。
文件上限仍为 1 MiB。工具不上传文件或摄像头画面，不自动运行接收文件。

如仍困难，请记录接收模式、实际采集分辨率、失败原因、尝试路径、耗时和摄像头型号。
能提供一张清楚显示码图细节的原始取景图片，会更便于针对性改进。
