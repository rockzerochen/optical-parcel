普通二维码文本功能 · 工具版本 1.4

使用
打开 Cimbar-Offline.html，点击顶部“普通二维码（文本）”。
全部编解码依赖已内置，不需要网络、服务器、Python 或 Node.js。
普通二维码用于一张静态码传输文本，不传输文件，不分帧。
本工具生成标准黑白 QR Code，可保存 PNG、SVG 或全屏展示。

生成参数
- 纠错等级：L / M / Q / H，按选择原样使用，不自动提高纠错等级。
- 版本：自动或固定 1–40。自动选择当前纠错等级下能容纳文本的最小版本。
- 掩膜：自动或固定 0–7。
- 每模块像素：2–24 的整数。
- 留白：4–16 个模块，保留识别所需边界。
- 图片边长上限 4096 像素；过大的组合会提示减小参数。
二维码的版本和纠错等级决定容量；图片变大不会增加容量。
修改参数/文本后，旧图会隐藏，保存按钮会禁用；点击生成后再传输。
如果选定版本放不下，会明确提示，不会截断文字或自动降低纠错等级。

中文与字符编码
生成始终使用 UTF-8 字节模式，并写入标准 ECI 26 编码标记。
普通中文通常占 3 个 UTF-8 字节，许多 emoji/生僻字占 4 个字节。
界面同时显示字符码点数和 UTF-8 字节数，应按字节数判断是否放得下。
二维码内容不会自动插入 UTF-8 BOM，不会去掉首尾空格，不会做 Unicode 归一化。
为一致地还原中文和 emoji，推荐用本工具或正确支持 UTF-8/ECI 的扫码器。
这项功能的静态单码容量远低于 Cimbar 的 1 MiB 文件上限。

识别
可用摄像头或选择本地图片。浏览器需要授予摄像头权限。
识别到一张码后停止摄像头，保留文本；切换到 Cimbar 页也会关闭二维码摄像头。
结果仅作为文本显示，不自动访问其中的网址或执行内容。
可复制原始文本，或保存为 UTF-8 TXT。
TXT 默认可选添加 BOM，便于较旧 Windows 文本软件识别中文；
该选项仅影响保存的 TXT，不会改变二维码或复制到剪贴板的文本。

外部二维码编码兼容
- 有 ECI 标记时按标记解码，不使用下拉框覆盖已声明的编码。
- 无 ECI 时自动优先严格 UTF-8；无法解码时尝试 GB18030。
  未声明编码的字节并非总能唯一判断；如果文字异常，可手选 UTF-8、
  GB18030/GBK/GB2312、Shift-JIS 或 ISO-8859-1，再次解码已扫描结果。
- 同时支持 QR 数字/英文、Kanji，以及新增 Hanzi 子集 1（GB2312）模式。
- 未支持的 ECI 编码不会输出猜测文字；非法字节不会静默替换为问号或替换字符。
- 不支持 Micro QR、结构化多码拼接和部分行业专用分段模式。

源码和依赖
生成器：Project Nayuki qrcodegen.js，MIT，完整依赖和许可已随包保存。
识别器：jsQR 1.4.0，Apache-2.0；本地扩展 Hanzi 模式和严格拒绝未知分段。
qr-codec.js 负责 UTF-8/ECI、参数和字节解码；qr-app.js 负责界面；
qr-worker.js 在 Worker 中识别。JS 及 Worker 源码全部嵌入最终 HTML。
开发者可在 source 目录执行 node build-qr-decoder.cjs，再执行 node build.cjs。
运行最终 HTML 不需要这些开发工具。Cimbar 1.3 核心未修改。
